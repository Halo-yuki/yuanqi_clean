# 元气大扫除 · 书院卫生评比小程序（学习版）

致元书院《元气大扫除 2026（试行）》配套小程序。数据存放本地，不需要服务器、不需要 AppID 也能跑通全流程。

---

## 一、在微信开发者工具里跑起来（按顺序做）

### 第 1 步：打开工具，导入项目
1. 打开 **微信开发者工具** → 点击 **「项目」→「导入项目」**（或左侧 `+` 号）。
2. **目录** 选择本项目文件夹（含 `project.config.json` 的这一层）：
   `...\WorkBuddy\2026-10-18-21-56-18\yuanqi-clean`
3. **AppID**：
   - 有自己 AppID → 直接填；
   - 也可以点 **「使用测试号」**（项目里默认留的是测试号占位 `touristappid`，导入时改成你的测试号即可）。
4. 后端服务：先 **不使用云服务**（本项目学习阶段用本地缓存）。
5. 点确定 → 工具会自动编译，模拟器显示首页。

> 若提示"项目配置文件无效"，把 `project.config.json` 里的 `"appid"` 改成一个真实的测试号/AppID 即可。

### 第 2 步：确认 5 个页面都能打开
`app.json` 里注册了 5 个页面，底部也有 5 个 tab（未配图标，只显示文字）：

| Tab | 页面 | 作用 |
|---|---|---|
| 规则 | `pages/index/index` | 展示评比规则 / 流程 / 照片要求 / 职责 / 注意事项 |
| 上传 | `pages/upload/upload` | 寝室长上传三张照片 |
| 评分 | `pages/score/score` | 评委按 5 个维度打分 |
| 榜单 | `pages/rank/rank` | 多维度得分 + 焕新之星 + 违规名单 |
| 我的 | `pages/mine/mine` | 切换身份、配置评委权限、维护寝室、数据管理 |

首次进入时会自动写入 6 间寝室 + 4 周历史评分的演示数据。

### 第 3 步：体验完整闭环（建议按这个顺序点）
1. **我的**：把身份切成 **寝室长**（选 B8-888），保存姓名 → 这是"寝室长上传照片"的前提。
2. **上传**：选本周 → 分别点三个照片位拍照/选图 → 提交 → 看到"我的提交记录"里多了一条。
3. **我的**：把身份切成 **年级中心组（张老师）**，可以在"评委名单"卡片里直接点 **「用此身份」**。
4. **评分**：选本周 → 点 B8-888 → 拖动 5 个维度滑块 → 看总分与自动评级 → 选互评结论 → 保存。
   - 若你用的是"年级中心组"，面板显示的是 **A—E 抽查评级**；管理员身份才会在面板顶部出现"交叉互评 / 现场抽查"切换。
5. **榜单**：切到本周 → 看到刚提交的寝室得分、五个维度条形图、本周达标标记；顶部是 **焕新之星**。
6. 回 **我的** → 数据管理 → **载入演示数据**，可以看满 4 周历史下的排名与处罚名单效果。

## 二、目录结构与每个文件的作用

```
yuanqi-clean
├─ project.config.json       项目配置（AppID、项目名、编译选项）
└─ miniprogram
   ├─ app.js                 全局入口，启动即初始化本地数据
   ├─ app.json               页面注册 + tabBar + 导航栏配色
   ├─ app.wxss               全局样式（元气绿主题 + 通用卡片/按钮/进度条）
   ├─ sitemap.json           索引配置
   ├─ utils
   │  ├─ rules.js       ★ 活动规则数据（评比规则/流程/照片要求/职责/注意事项）
   │  │                  ★ 5 个评分维度、A—E 评级、角色定义、优秀率上限
   │  ├─ util.js              周次计算、时间节点（环节/上传窗）、时间格式化
   │  ├─ store.js       ★ 数据层：寝室/提交/评分/评委/身份 的读写 + 照片存本地
   │  └─ stats.js       ★ 统计层：多维度均分、互评优秀率、达标周、违规、焕新之星
   └─ pages
      ├─ index/   首页（规则卡片可折叠 + 活动环节进度 + 快捷入口）
      ├─ upload/  寝室长上传（三个固定照片位 + 提交记录 + 删除）
      ├─ score/   评委打分（照片预览 + 5 维度滑块 + 结论 + 备注 + 标记不合格）
      ├─ rank/    榜单（焕新之星 / 月度候选 / 本周得分榜 / 处罚名单）
      └─ mine/    我的（身份切换 + 评委权限配置 + 寝室名单 + 数据管理）
```

每个页面 4 个文件：`.js`（逻辑）`.wxml`（结构）`.wxss`（样式）`.json`（页面配置）。

## 三、五个功能需求分别落在哪

| 需求 | 实现位置 |
|---|---|
| 1. 规则展示 | `utils/rules.js`（数据） → `pages/index`（折叠卡片渲染） |
| 2. 寝室长上传照片 | `pages/upload`，三个固定照片位由 `rules.js` 的 `PHOTO_SLOTS` 驱动；照片用 `wx.chooseMedia` 拍摄后 `saveFile` 落盘 |
| 3. 指定用户评分 | `pages/mine` 配置评委名单（启用/停用/角色）→ `pages/score` 按角色显示不同结论控件；非评委角色进入评分页会被拦住 |
| 4. 多维度得分 | `rules.js` 的 `DIMENSIONS`（地面清洁/桌面整齐/物品归置/洗手池镜面/整体整洁度，各 20 分）；打分在 `score`，展示在 `rank`（点击寝室展开维度条） |
| 5. 焕新之星 | `utils/stats.js` 的 `buildOverview`：无违规 + 累计达标周数（互评优秀率 ≥75% 且抽查 A 级）排名前三 → `pages/rank` 顶部展示 |

业务规则要点也已落地：
- 生活委员互评优秀占比 **≤ 2/3**：`score.js` 的 `saveReview` 提交时强制校验。
- 抽查 **≤ C 级**、互评不合格、未上传/照片不合格 → 累计 3 次进入处罚名单：`stats.js`。
- 照片上传时间窗（周日 22:00—周一 8:00）：`util.js` 的 `isUploadWindow`，逾期提交会被标记"逾期"。

## 四、想改文案 / 改规则怎么改

只改 `miniprogram/utils/rules.js` 一个文件即可，页面会自动跟着变（页面是按数据渲染的）：

- `SECTIONS`：首页 5 个规则卡片的内容（支持 `text / sub / bullets / table / cards` 五种块）。
- `DIMENSIONS`：评分维度名称、满分值。
- `GRADE_RULES`：总分 → A—E 的分数线。
- `PHOTO_SLOTS`：固定三张照片的要求。
- `ROLES`：角色与权限说明。
- `MUTUAL_EXCELLENT_LIMIT` / `STAR_EXCELLENT_RATE` / `VIOLATION_LIMIT`：三个阈值。

## 五、下一步：接云开发（可选）

现在数据写在 `wx.setStorageSync`，换手机/清缓存就没了。想变成真正可用的版本：

1. 开发者工具里点 **「云开发」** 开通环境，拿到环境 ID。
2. `app.js` 的 `onLaunch` 里加：
   ```js
   wx.cloud.init({ env: '你的环境ID', traceUser: true })
   ```
3. 建集合 `rooms / submissions / reviews / raters`，把 `utils/store.js` 里各个 `getXxx / addXxx` 换成：
   ```js
   wx.cloud.database().collection('rooms').get()      // 原来：read().rooms
   wx.cloud.database().collection('rooms').add({ data }) // 原来：写入本地
   ```
4. 照片改存云存储：`wx.cloud.uploadFile({ cloudPath, filePath })` 返回 `fileID`，直接当图片 `src` 用。
5. 页面代码一行都不用改 —— 页面只依赖 `store` 暴露的方法名。
